# 링크 하나로 설치 (편남 6화)

사용자가 **편남 유튜브 링크**를 주면서 "이거 보고 그대로 설치해줘" 하면,
이 문서대로 따라가면 된다. 회차마다 따로 배울 필요 없다.

```
https://youtu.be/2QFId5PBwm8 이거 그대로 설치해줘
```

---

## 1. 링크에서 영상 ID 꺼내기

편남 링크는 아래 형태 중 하나다. **11자 영상 ID**만 뽑으면 된다.

| 형태 | 예 |
|---|---|
| `youtu.be/ID` | `https://youtu.be/2QFId5PBwm8` |
| `youtube.com/watch?v=ID` | `https://www.youtube.com/watch?v=2QFId5PBwm8` |
| `youtube.com/shorts/ID` | `https://www.youtube.com/shorts/BkUnxJhp5ug` |

뒤에 `?si=...`, `&t=30` 같은 게 붙어 있어도 **ID만** 쓴다.

> **유튜브 페이지를 열어 설명란을 읽으려 하지 말 것.** 유튜브는 내용을 나중에 그려 넣어서
> 웹으로 가져오면 설명란이 비어 있다. 아래 2번처럼 ID로 명세를 찾는 쪽이 확실하다.

## 2. 명세 찾기

색인을 읽는다.

```
https://raw.githubusercontent.com/PNam-Up/claude-code-kit/main/specs/index.json
```

`episodes` 에서 `video_id` 가 일치하는 항목을 찾아, 그 `spec` 파일을 같은 폴더에서 읽는다.
예를 들어 `ep4.json` 이면:

```
https://raw.githubusercontent.com/PNam-Up/claude-code-kit/main/specs/ep4.json
```

**색인에 없는 ID면** 아직 명세가 없는 회차다. 지어내지 말고 이렇게 말한다.

> 이 영상은 아직 자동 설치 명세가 없습니다. 영상 설명란의 안내를 따라 주세요.

## 3. 선행 회차 확인

명세의 `requires` 에 적힌 회차가 먼저 깔려 있어야 한다. 보통 `[1]`(AI 비서)이다.

- 이미 깔려 있으면 넘어간다. (지금 이 대화가 그 비서 안에서 돌고 있다면 1화는 된 것이다)
- 안 깔렸으면 **그 회차 명세부터** 같은 방식으로 처리한 뒤 돌아온다.
- `recommends` 는 없어도 진행한다. 다만 "이게 있으면 이런 것도 된다"고 한 번 알려 준다.

## 4. 파일 받기

`files` 의 각 항목을 `url` 에서 받는다. 규칙이 있다.

- `read_first: true` 인 파일은 **먼저 읽고** 그 안의 절차를 따른다. 대개 그 파일이 본문이고,
  이 명세는 목차 역할만 한다.
- `when` 이 있으면 조건이 맞을 때만 받는다. (`"맥을 쓰면"` → 사용자 환경을 확인하고 판단)
- `optional: true` 는 사용자가 원할 때만.
- 명세에 `choose` 가 있으면 **먼저 사용자에게 물어** 고르게 한 뒤 고른 것만 받는다.

## 5. 단계 실행 — 여기가 핵심

`steps` 를 번호 순서대로 진행하되, **`actor` 를 반드시 보고 갈라야 한다.**

### `actor: "ai"` — 네가 한다

설명대로 실행한다. 중간에 사용자에게 물을 게 생기면 묻되, 진행 자체는 네가 한다.

### `actor: "human"` — **멈추고 사용자에게 넘긴다**

네가 대신 할 수 없는 일이다. 계정 인증, 브라우저 동의, 폰에서 누르는 권한 같은 것들이다.
**절대 됐다고 가정하고 넘어가지 말 것.** 이렇게 한다.

1. `do` 를 사용자가 할 일로 풀어서 말한다
2. `why` 를 덧붙여 **왜 대신 못 하는지** 알려 준다 (안 그러면 게으른 걸로 보인다)
3. `guide` 가 있으면 누를 순서를 그대로 알려 준다
4. **끝났다는 답을 받은 뒤에** 다음 단계로 간다

말투 예시:

> 여기서부터는 제가 못 합니다. **텔레그램 봇 토큰**은 본인 계정으로만 발급돼요.
>
> 1. 텔레그램에서 `@BotFather` 를 검색해 대화를 엽니다
> 2. `/newbot` 을 보내고 이름을 정합니다
> 3. 나오는 토큰 문자열을 저에게 붙여넣어 주세요
>
> 다 되면 알려 주세요. 받는 대로 이어서 설치하겠습니다.

## 6. 확인

전부 끝나면 명세의 `verify` 를 사용자와 같이 확인한다.
알림이 오는지, 답이 오는지 **실제로 한 번 돌려 보고** 마친다.
"설치했습니다"로 끝내지 말 것 — 동작을 봐야 끝난 것이다.

---

## 지켜야 할 것

- **명세에 없는 걸 지어내지 않는다.** 파일 주소든 단계든, 명세에 있는 것만 쓴다.
  명세가 부실하면 "명세에 이 부분이 없다"고 말하고 사용자에게 묻는다.
- **`actor: human` 을 건너뛰지 않는다.** 이걸 건너뛰면 나중에 반드시 막히는데,
  그때는 어디서부터 잘못됐는지 찾기가 훨씬 어렵다.
- **사용자 환경을 먼저 확인한다.** 맥인지 윈도우인지, 이미 깔린 게 뭔지.
  묻지 않고 한쪽으로 단정하면 엉뚱한 파일을 받는다.
- **받은 파일을 요약하지 말고 그대로 읽고 따른다.** `read_first` 파일에는 이미 상세 절차가
  들어 있다. 네가 다시 정리하면 빠지는 단계가 생긴다.
- 설치 중 실패하면 **어느 단계에서 왜 실패했는지** 말하고 멈춘다. 다음 단계로 밀고 가지 않는다.

## 한 번에 여러 회차

사용자가 링크를 여러 개 주면 **회차 번호 순서대로** 처리한다.
겹치는 선행 회차(1화 같은 것)는 한 번만 한다.
사람이 해야 하는 단계는 **모아서 한 번에** 안내하면 왔다 갔다 하지 않아도 된다.
